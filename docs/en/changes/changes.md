## 11.2.0

#### Project
* Fix the release script on macOS: the source tarball carried an AppleDouble `._*` entry and `com.apple.provenance` xattr headers for every file (the 11.0.0 source release has them, and GNU tar extracts them as stray `._*` files with a warning per entry), the next-version PR step aborted because the single-branch release clone has no remote-tracking ref for the pushed branch, and the vote email left out the BanyanDB client proto submodule.

#### OAP Server
* Fix the Cilium fetcher dropping or double-reading Cilium nodes. The Peer notify stream, the cluster watcher and the 10-second refresh timer rebuilt the shared node list without a lock, which could open two flow streams for one node or keep a closed node as in use. A node closed when this OAP's share of nodes moved away was reused, still closed, when the share moved back (e.g. after scaling the OAP cluster out and back in), so that node went unread while the assignment lasted. A `Receiver`-role OAP on a ZooKeeper, Consul, Nacos or etcd coordinator never finds itself in the cluster list and, when Cilium nodes and other OAPs were listed, threw on every refresh; it now skips Cilium fetching quietly, as the `Mixed` and `Aggregator` OAPs share all Cilium nodes among themselves.
* Fix the gRPC alarm hook throwing a `NullPointerException` on every alarm until OAP restart: once an alarm fired while no gRPC hook was configured (at boot, or after the hooks were removed through dynamic configuration), adding a gRPC hook later broke it. Also shut down the client of a gRPC hook removed from the configuration.
* Fix the Cilium fetcher silently stopping a Cilium node's flow stream. When a stream failed and was retried (e.g. a Cilium agent restart), the ended stream's thread interrupt stayed registered on its node, so closing that node later (e.g. when the OAP cluster scaled) interrupted whichever stream the pooled thread then ran for another node, and an interrupted stream is treated as closed and never retried. A stream that started just as its node closed was also never interrupted. Each stream now registers before it opens and deregisters when it ends, and a closed node refuses new registrations.
* Fix one gRPC alarm hook with a malformed target, such as `http://host` or `host:port` as the host, stopping every gRPC hook: building its client threw and aborted the whole gRPC callback on each alarm, and a malformed target in the static alarm settings stopped OAP from starting. That hook is now skipped with an error log, at boot too, and a hook whose target becomes malformed keeps its previous client.
* Make the cluster coordinator's watcher list safe for a watcher that registers after the coordinator started, as the Cilium fetcher does: the plain list shared with the coordinator's notify thread could throw a `ConcurrentModificationException` there or miss the new watcher.
* Add the `OTLP_VIRTUAL_GATEWAY` layer: the OTLP trace analysis draws a gateway listed in `gateways.yml` as a node of this layer, the OTLP counterpart of the agent path's `VIRTUAL_GATEWAY`, as it already puts the databases, caches and brokers it conjectures under the `OTLP_VIRTUAL_*` layers. The shipped `tal/otlp-general.yaml` uses it; a copy of the rule file made from an earlier release keeps drawing `VIRTUAL_GATEWAY` until it is updated.
* The analysis of SkyWalking agents' traces now runs as Trace Analysis Language (TAL) rules, like the OpenTelemetry trace analysis, and can be read and extended the same way. The rule files are listed in the new `trace-analyzer` setting `nativeTalFiles` (`SW_TRACE_NATIVE_TAL_FILES`) and ship under `config/tal/`. Metrics, topology and stored traces stay the same, apart from two edge cases: where a tag is looked up by its key, such as the tags kept with service and endpoint metrics, a span that repeats the key now gives its first value (and a cache span with a repeated key is now analyzed instead of failing its segment), and a segment that fails during analysis no longer sends AI evaluation samples.
* Uninstrumented gateways in `gateways.yml` now also match a bare host in SkyWalking agents' traces, as they already did in OpenTelemetry traces: an address written without a port, as an HTTP client records it when it omits the default port, matches the gateway listed at port 80 (or listed without a port), so a gateway is listed once. Port 443 is not inferred: a bare host is retried only at port 80, so a gateway configured at port 443 matches only an address that includes `:443`.
* `SW_TRACE_ANALYZER=-` now stops the OAP from starting while the native trace receiver (on by default) or the Kafka fetcher is enabled, because they need the `trace-analyzer` module to analyze agents' traces. Without either of them, it still turns off the OpenTelemetry trace analysis as before.
* The log lines of the agent trace analysis moved to new logger names, one per rule file: `org.apache.skywalking.trace.analysis.script.<file>`, such as `org.apache.skywalking.trace.analysis.script.native-rpc` for what `RPCAnalysisListener` logged. Update a logging configuration that names one of the old listener classes; the Native Trace Analysis doc lists the new names.
* TAL rules can now assign a declared variable with `=`, loop with `foreach`, write log lines with `log`, use typed layer values (`as Layer`), and limit a rule file to loaded modules with `requiredModules`; more functions, `toJson` and `toJsonArray` among them, can be called anywhere a value goes. A custom rule that uses `source`, `foreach`, `in`, `build`, `first`, `segmentDef`, `writeNetworkAlias` or `log` as a variable name has to rename it, as they are now keywords.
* TAL rules write their records with `source {}`, such as `source DatabaseSlowStatement {}`, which an OpenTelemetry rule sends where it is written. The OpenTelemetry rules' `outputType` key and `sink {}` block are removed: a custom rule file written for 11.1.0 that uses them fails to load until its record moves to a `source {}`, as the shipped `otlp-slow-sql` rule now writes its slow statement.
* AI evaluation samples natively stored OpenTelemetry spans (`otlpTraceStorage: otlp`) through the new `otlp-ai-evaluation` TAL rule, listed in `trace-analyzer`'s default `talFiles`, instead of its span listener. It is declared for the `OTLP_GENERAL` layer, like the other shipped OpenTelemetry rules, so it sees only the spans of services that set `service.layer=OTLP_GENERAL`: a GenAI application whose spans should be evaluated sets that resource attribute, for example `OTEL_RESOURCE_ATTRIBUTES=service.layer=OTLP_GENERAL`. A deployment that sets `talFiles` (`SW_TRACE_TAL_FILES`) adds `otlp-ai-evaluation` to it. Zipkin spans, and OpenTelemetry spans stored as Zipkin spans, are sampled as before.
* Fix a webhook alarm hook not being posted when the alarm also names a hook of another type: the webhook callback looked up the other hook's name in the webhook settings and threw a `NullPointerException`. Depending on the hook names, the webhook was never posted (for example `webhook.default` with `gRPC.default`), or an error was logged on every alarm.
* Add `alarm.default.grpcTimeout` / `SW_ALARM_GRPC_TIMEOUT`, the deadline in seconds of each gRPC alarm hook stream (default `10`, which was the fixed deadline before).
* Record gRPC alarm hook deliveries on the alarm delivery self-observability metrics (`alarm_http_delivery_total` and `alarm_http_delivery_latency_seconds`) with `hook_type=gRPC`, so the OAP dashboards show the gRPC hook as one more channel.

#### Documentation
* Document how a release is named in the release guide: a few words that state its key features, used as the GitHub release title `x.y.z - <release name>`, which the guide's `gh release create` example now uses in place of the bare version.
* Update the release guide for the redesigned website and add a release-name section to the GitHub release body.
* Fix the Zabbix receiver doc's links to the Zabbix documentation, which moved in Zabbix 8.0, by pinning them to Zabbix 6.0.
* Describe the sampling convention in the `sw8` protocol doc: the SkyWalking agents always write `1` as the Sample value and don't use it, and an agent that receives a valid `sw8` header should keep the upstream sampling decision instead of applying its own sampling rate.
* Reorganize the tracing docs by where traces come from: a tracing overview, then setup, bundled analysis and TAL pages for SkyWalking native traces and for OpenTelemetry traces, and the Zipkin pages. The Zipkin receiver's sampling settings moved from the trace sampling doc to the Zipkin trace doc.
* Fix the trace sampling doc's setting name, `default.rate`, and its example rates, and document the OpenTelemetry span metadata fallbacks, that metrics shared across TAL rules must also agree on `labelLimit`, and, on the Virtual GenAI page, the `service.layer=OTLP_GENERAL` that the AI evaluation of natively stored OpenTelemetry spans needs.
